# Участие в разработке ГОСТ Analyzer

Этот документ описывает общий процесс разработки проекта ГОСТ Analyzer.

## Основные ветки

### `main`

Стабильная версия проекта.

Прямые изменения в `main` запрещены.

Изменения попадают в `main` только после проверки интеграционной версии проекта.

### `dev`

Основная ветка разработки.

Все рабочие ветки создаются от `dev`.

---

## Создание рабочей ветки

Перед началом работы необходимо обновить `dev`:

```bash
git switch dev
git pull
```

После этого создаётся отдельная ветка под задачу:

```bash
git switch -c feature/BE-01-example
```

Используемые типы веток:

```text
feature/   новая функциональность
fix/       исправление ошибки
infra/     инфраструктура и DevOps
test/      тестирование
docs/      документация
chore/     технические изменения
```

Примеры:

```text
feature/FR-01-api-sync
feature/BE-01-jwt-auth
feature/DOC-01-preserve-document
feature/ML-01-api-contract

fix/BE-02-tests

infra/DO-01-docker

test/QA-01-regression-tests
```

## Коммиты

Коммит должен описывать одно логическое изменение.

Рекомендуемый формат:

```text
тип: краткое описание
```

Примеры:

```text
feat: add project creation endpoint
fix: preserve tables during document processing
test: add authentication tests
docs: update API documentation
chore: configure repository
```

## Pull Request

После завершения задачи:

```bash
git add .
git commit -m "feat: description"
git push -u origin branch-name
```

После этого создаётся Pull Request:

```text
рабочая ветка → dev
```

В Pull Request необходимо указать:

- что было сделано;
- зачем внесены изменения;
- как проверить результат;
- какие тесты выполнены;
- связанный Issue.

## Code Review

Автор Pull Request не должен самостоятельно принимать собственный PR без проверки другим участником команды.

Перед объединением необходимо убедиться, что:

- код запускается;
- изменения соответствуют задаче;
- отсутствуют секреты и локальные файлы;
- тесты проходят;
- нет критических замечаний.

## Definition of Done

Задача считается завершённой, когда:

- функциональность реализована;
- выполнена локальная проверка;
- основные ошибки обработаны;
- добавлены или обновлены тесты;
- при необходимости обновлена документация;
- создан Pull Request;
- выполнен Code Review;
- QA подтвердил работу;
- изменения объединены в `dev`.

## Запрещено

Не допускается:

```text
push напрямую в main
commit файлов .env
commit паролей и токенов
commit node_modules
commit виртуальных окружений Python
commit пользовательских документов
commit результатов генерации
```
